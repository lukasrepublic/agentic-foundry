# governance

Rules ship as kits under `governance/kits/<category>/` (`kit.yaml`, `rules.yaml`, `README.md`, `checks/`,
`templates/`). Kits are read from the plugin at the locked version; they are never copied into a workspace.

In an adopter workspace:

- `governance/local/` is the adopter layer: private rules (`<ORG>-…` ids, never `FG-`), overrides,
  `exceptions.yaml`, `baselines/`.
- `governance/rendered/` is generated by `scripts/foundry_governance.py render`. Do not edit it.
- `.foundry/governance.lock` is machine-owned.

Verbs: `load`, `validate`, `render`, `applicable --paths`, `check`, `exceptions`, `baseline`.
Exit 0 ok, 1 findings, 2 refused. No verb uses the network.

Local file shapes. `governance/local/rules.yaml`: `rules:` (adopter rules) and `overrides:` (a rule `id`
plus the fields to change; refused for a `floor` rule). `governance/local/exceptions.yaml`: `exceptions:`
with `rule`, `scope`, `reason`, `owner`, `expires` (YYYY-MM-DD).
