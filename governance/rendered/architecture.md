# Governance: architecture

Generated by `scripts/foundry_governance.py render`. Do not edit. Effective rules (kits + governance/local). Details live in the source files.

## FG-ARCH-001 - Layers and allowed dependency direction

A project MUST declare its layers and the allowed dependency direction between them (the stack profile architecture.allowed_dependencies) and MUST enforce that direction with the ecosystem tool in the bindings table.

- level 1, active
- applies to: `**`
- check: ci -> `governance/kits/architecture/checks/bindings.yaml#layers`

## FG-ARCH-002 - No dependency cycles

The dependency graph between modules and layers MUST be free of cycles, checked by the tool in the bindings table.

- level 1, active
- applies to: `**`
- check: ci -> `governance/kits/architecture/checks/bindings.yaml#cycles`

## FG-ARCH-003 - External dependency allow and deny per layer

Each layer MUST list the external packages it may import; an import outside that list MUST fail the architecture check.

- level 1, active
- applies to: `**`
- check: ci -> `governance/kits/architecture/checks/bindings.yaml#external`

## FG-ARCH-004 - Architecture model is code

A project SHOULD keep one C4 model as code (Structurizr DSL or equivalent) and SHOULD derive its views from it instead of drawing them by hand.

- level 2, active
- applies to: `**`
- check: review-lens -> `agents/pr-reviewer.md`

## FG-ARCH-005 - ADR format and numbering

A decision MUST be recorded as a MADR file docs/decisions/NNNN-title.md with a status, a unique number and, for a superseded decision, a resolvable superseded-by link.

- level 1, active
- applies to: `docs/decisions/**`
- check: lint -> `governance/kits/architecture/checks/adr_lint.py`

## FG-ARCH-006 - ADR names the check that confirms it

An accepted ADR MUST carry confirmation.check_id naming the rule id or check that enforces it, or the literal value none together with confirmation.reason.

- level 1, active
- applies to: `docs/decisions/**`
- check: lint -> `governance/kits/architecture/checks/adr_lint.py`

## FG-ARCH-007 - ADRs are immutable once accepted

An accepted ADR MUST NOT be rewritten. A changed decision MUST be a new ADR that supersedes the old one.

- level 2, active
- applies to: `docs/decisions/**`
- check: review-lens -> `agents/pr-reviewer.md`

## FG-ARCH-008 - Fitness functions run in CI with a committed baseline

Every tool-bound architecture rule MUST run in CI as a gate. On a brownfield codebase, known violations MUST be frozen in a committed baseline so that only new violations fail.

- level 1, active
- applies to: `**`
- check: ci -> `governance/kits/architecture/templates/architecture-fitness.yml`
