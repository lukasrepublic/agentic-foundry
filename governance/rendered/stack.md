## FG-STK-001 - Use the approved stack

A project MUST use the frameworks, libraries and tools approved by its stack profile and conventions.

## FG-STK-002 - Every version is pinned

Container image references, Helm chart revisions and external GitHub Actions references MUST be pinned (an image digest or exact version, an exact chart version, a full commit SHA); the rego checks exactly these. Every other toolchain, runtime and library version MUST be pinned in the project's version matrix and lock (FG-STK-004), which is the surface for everything the rego does not read.

- level 1, active
- applies to: `**`
- check: ci -> `governance/kits/stack/checks/pinning.rego`

## FG-STK-003 - CI actions are pinned to a commit SHA

Every external GitHub Actions uses: reference MUST be pinned to a full 40-character commit SHA.

## FG-STK-004 - Versions are recorded with a research timestamp

A project MUST keep one version matrix and a lock of the pinned versions, and every version-bearing template MUST carry the date its versions were researched. A version change MUST be a reviewed edit to both.

- level 2, active
- applies to: `**`
- check: review-lens -> `agents/pr-reviewer.md`
